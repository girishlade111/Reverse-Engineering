========================================================================
MISSION
========================================================================
Enterprise Reverse Engineering Prompt Framework
Version: 3.0

========================================================================
CORE MISSION STATEMENT
========================================================================

To enable any AI agent to perform a complete, accurate, and
comprehensive reverse engineering of any software repository,
producing documentation of such quality that it serves as a
definitive reference for developers, architects, and stakeholders.

========================================================================
VISION
========================================================================

A world where no software system is a black box. Where every
repository can be understood completely, documented thoroughly,
and rebuilt faithfully from its documentation alone.

========================================================================
PRINCIPLES
========================================================================

PRINCIPLE 1: ABSOLUTE THOROUGHNESS
Every file, every folder, every function, every class, every
interface, every dependency, every configuration, every script,
every build file, every test, every document, every comment,
every commit message - everything in the repository matters.
Nothing is too small to be understood.

PRINCIPLE 2: EVIDENCE SUPREMACY
Every statement about the repository must be traceable to
specific evidence in the code. "I think" and "probably" are
not acceptable without explicit qualification. The code is
the truth. Everything else is interpretation.

PRINCIPLE 3: SYSTEMS THINKING
No component exists in isolation. Every file is part of a module.
Every module is part of a subsystem. Every subsystem is part of
the system. Understanding requires tracing these connections.

PRINCIPLE 4: COMPLETE DOCUMENTATION
Understanding that is not documented is not understanding.
Documentation must be complete, accurate, organized, and
accessible to its intended audience.

PRINCIPLE 5: CONTINUOUS VALIDATION
Every phase validates the findings of the previous phase.
Cross-referencing is continuous. Inconsistencies are investigated,
not ignored.

PRINCIPLE 6: SCALABLE METHODOLOGY
The approach must work for a 10-file library as effectively as
a 10,000-file enterprise application. Adaptation is built into
the framework, not applied as an afterthought.

PRINCIPLE 7: PRODUCTION READINESS
Documentation generated by this framework must be of sufficient
quality to serve as the primary reference for production systems.
It must be accurate enough for debugging, complete enough for
onboarding, and structured enough for maintenance.

========================================================================
END OF MISSION
