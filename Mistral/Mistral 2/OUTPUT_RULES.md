DOCUMENTATION CONTENT RULES### General- Always include metadata (name, type, path, version, timestamp)- Use consistent heading hierarchy- Include file paths, line numbers, code references- Use Mermaid diagrams for all relationships and flows- Cross-reference all related components### Architecture- Include high-level overview- Include component diagrams- Document all major components and relationships### Code- Document purpose and responsibilities- Document all parameters with types- Document return values and side effects- Include real code examples### Diagrams- Must be technically accurate- Use standard notations (UML, Mermaid)- Include legends- Keep readable at normal zoom
