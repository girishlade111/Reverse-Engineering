# GLOSSARY

## Terminology and Definitions for Reverse Engineering Framework

---

## A

### Accuracy
The degree to which documentation correctly represents the actual code. Measured by claim verification rate.

### Architectural Decision Record (ADR)
A document capturing a significant architectural choice, its context, and consequences.

### Architecture Pattern
A fundamental structural organization pattern defining how components relate and interact.

### Assumption
A belief about the system not directly verified in code but inferred from evidence.

---

## B

### Business Logic
The core rules and workflows that implement business requirements in the software.

---

## C

### Call Graph
A directed graph showing which functions call which other functions.

### Claim
An assertion about the system that requires evidence support.

### Component
A modular, deployable unit of composition with clear boundaries and responsibilities.

### Confidence Level
Indicator of certainty: Certain, Confident, Probable, Speculative, or Unknown.

### Control Flow
The order in which code executes, including branches, loops, and function calls.

### Cross-Reference
A link or reference from one part of documentation to another.

---

## D

### Data Flow
The movement of data through the system, including transformations.

### Dependency
A relationship where one module/component requires another to function.

### Dependency Graph
A graph showing dependencies between modules or packages.

### Design Pattern
A reusable solution to a commonly occurring problem in software design.

---

## E

### Entry Point
A location where program execution begins (main function, route handler, etc.).

### Evidence
Code-based proof supporting a claim (file references, line numbers, excerpts).

### Execution Path
A specific sequence of code executed during program run.

### External System
A system outside the repository boundary that interacts with the analyzed system.

---

## F

### Framework
A pre-built structure providing generic functionality that can be specialized.

### Function Documentation
Documentation describing a function's purpose, parameters, return value, and side effects.

---

## I

### Import Analysis
Examination of import statements to understand dependencies.

### Interface
A contract defining what methods/properties a component must implement.

---

## L

### Layer
A horizontal architectural division grouping related functionality.

### Library
A collection of pre-written code that can be reused across projects.

---

## M

### Mermaid
A JavaScript-based diagramming and charting tool used for embedded diagrams.

### Module
A self-contained unit of code organization, often corresponding to a directory or package.

---

## P

### Pattern Recognition
Identifying common architectural or design patterns in code.

### Prompt
An instruction set given to an AI agent to perform analysis tasks.

### Prompt Chain
A sequence of prompts executed in order, each building on previous results.

---

## Q

### Quality Dimension
A measurable aspect of documentation quality (Accuracy, Completeness, Clarity, Usefulness).

---

## R

### Repository Discovery
The initial phase of scanning and inventorying all repository contents.

### Reverse Engineering
The process of analyzing a system to identify its components and relationships.

---

## S

### Self-Validation
The process of checking one's own work against quality criteria before submission.

### Sequence Diagram
A diagram showing interactions between objects over time.

### State Machine
A model describing states and transitions in a system.

### Static Analysis
Analysis performed without executing the code.

### Technology Stack
The set of technologies (languages, frameworks, libraries) used in a system.

---

## T

### Template
A pre-defined structure for consistent documentation output.

### Test Coverage
The percentage of code exercised by tests.

---

## U

### Uncertainty Level
Classification of how certain a conclusion is based on available evidence.

---

## V

### Validation Checklist
A list of criteria to verify before considering work complete.

### Version Tracking
Recording document versions and change history.

---

## Framework-Specific Terms

### PROMPT_01 through PROMPT_14
The numbered execution prompts in this framework.

### Core Documents
MISSION.md, OPERATING_RULES.md, QUALITY_STANDARDS.md, OUTPUT_RULES.md

### Master Documents
MASTER_INDEX.md, MASTER_PROMPT.md, PROJECT_SPECIFICATION.md, PROMPT_DESIGN_GUIDE.md

### Phase Gates
Checkpoints between major phases requiring completion criteria.

### Continuation Protocol
Procedure for handling analyses that exceed response limits.

---

*This glossary defines all key terms used throughout the Enterprise Reverse Engineering Prompt Framework.*
